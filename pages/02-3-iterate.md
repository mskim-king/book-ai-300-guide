> 📅 **최종 확인**: 2026-11-21

한 번의 프롬프트로 완벽한 결과를 얻기는 어렵습니다. AI 활용을 잘하는 사람은 첫 결과를 **초안으로 보고, 대화로 다듬어 완성**합니다. 이 페이지에서는 결과를 효율적으로 고치는 대화 방법을 다룹니다.

## 요약

- 첫 결과는 초안입니다. **무엇이 마음에 들고 무엇이 아쉬운지** 구체적으로 알려 줍니다.
- 고칠 부분을 **콕 집어** 요청하면 나머지 좋은 부분이 유지됩니다.
- 대화가 길어져 엉키면 **정리해서 새 대화로** 시작합니다.

## 피드백은 구체적으로

**❌ 막연한 피드백**
```text
별로야. 다시 써 줘.
```
→ AI는 무엇이 문제인지 모르기 때문에 전혀 다른 방향으로 다시 쓰거나 비슷한 결과를 냅니다.

**✅ 구체적인 피드백**
```text
전체 구성은 좋아. 다음 두 가지만 고쳐 줘.
1. 첫 문단이 너무 길어. 2문장으로 줄여 줘.
2. 세 번째 근거는 우리 회사와 관계없으니 빼고, 비용 절감 사례로 바꿔 줘.
나머지 문장은 그대로 둬.
```

좋은 피드백에는 세 가지가 들어갑니다.

| 요소 | 예시 |
|---|---|
| 유지할 것 | "전체 구성은 좋아", "나머지는 그대로 둬" |
| 바꿀 것 | "첫 문단", "세 번째 근거" |
| 바꾸는 방향 | "2문장으로", "비용 절감 사례로" |

## 자주 쓰는 다듬기 요청

```text
더 짧게: "핵심만 남기고 절반 분량으로 줄여 줘."
더 쉽게: "처음 듣는 사람도 알 수 있게 다시 설명해 줘."
여러 안: "같은 내용으로 어조가 다른 버전 3개를 보여 줘."
비교:   "A안과 B안의 장단점을 표로 비교해 줘."
골라 합치기: "1안의 도입부와 3안의 결론을 합쳐 줘."
형식 변경: "이 내용을 슬라이드 5장 개요로 바꿔 줘."
```

[[TIP("요령: 여러 안을 먼저 받기")]]

방향이 확실하지 않을 때는 처음부터 하나를 고치기보다 **서로 다른 안을 3개** 받아 보세요. 고르는 것이 고치는 것보다 빠르고, 내가 원하는 방향도 분명해집니다.

[[/TIP]]

## 대화가 길어지면 새로 시작하기

같은 대화에서 수정을 여러 번 반복하면 앞의 조건과 뒤의 조건이 섞여 결과가 엉킬 수 있습니다. 이럴 때는 지금까지의 요구 사항을 정리해 **새 대화**에서 시작하는 것이 더 빠릅니다.

```text
지금까지 우리가 합의한 요구 사항을 하나의 프롬프트로 정리해 줘.
새 대화에서 이 프롬프트만으로 같은 결과를 만들 수 있게 써 줘.
```

이렇게 정리한 프롬프트는 다음에 같은 일을 할 때 그대로 다시 쓸 수 있습니다. 자주 쓰는 프롬프트는 04장 레시피처럼 모아 두면 좋습니다.

## 다듬기 흐름 한눈에 보기

```text
1. 5요소로 첫 요청 → 초안 받기
2. 유지할 것 / 바꿀 것 / 방향을 알려 주기
3. 필요하면 여러 안을 받아 고르기
4. 엉키면 요구 사항을 정리해 새 대화로
5. 완성된 프롬프트는 저장해서 재사용
```

## 실무 체크포인트

- [ ] 피드백에 유지할 것·바꿀 것·방향을 모두 담았는가
- [ ] 고칠 부분을 콕 집어 요청했는가
- [ ] 방향이 불확실할 때 여러 안을 먼저 받아 봤는가
- [ ] 잘 된 프롬프트를 정리해 저장했는가
